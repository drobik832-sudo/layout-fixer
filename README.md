# layout-fixer

Автоисправление раскладки клавиатуры для **GNOME / Wayland** — аналог xneur и
Punto Switcher. Работает на уровне ядра (`evdev` + `uinput`), потому что на
Wayland приложение не может ни подслушать, ни отправить чужие нажатия клавиш.

## Что умеет

* распознаёт слова, набранные не в той раскладке, и перепечатывает их правильно;
* понимает **одиночный тап левого Alt** как переключение раскладки, но не
  переключает язык внутри комбинаций (`Alt+Tab`, `Ctrl+Alt+T`, `Shift+Alt`) —
  то, чего не умеет системная xkb-опция `grp:lalt_toggle`, из-за которой
  раскладка менялась на каждом нажатии Alt, то есть посреди печати;
* работает с несколькими клавиатурами и переживает их подключение на ходу;
* при создании виртуальной клавиатуры убирает лишнюю группу, которую
  xf86-input-evdev добавляет в раскладку: со списком `us, ru, ru` переключение
  циклит `us -> ru -> ru(ничего) -> us` и примерно каждое второе нажатие выглядит
  как «ничего не произошло»;
* после исправления остаётся в целевой раскладке, чтобы можно было продолжить набирать;
* по умолчанию работает в **режиме наблюдения** (только логирует решения).

## Требования

* Linux с GNOME и **Wayland** (проверено на Zorin OS 18.1, GNOME Shell 46);
* системные пакеты: `python3-evdev`, `python3-gi`, словари `hunspell-ru`,
  `hunspell-en-us` (в Zorin/Ubuntu они уже стоят);
* доступ на запись к `/dev/uinput` — см. «Установка».

## Установка

```bash
# 1. Окружение (system-site-packages нужен для gi/PyGObject из системы)
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -e . --no-build-isolation

# 2. Права на /dev/uinput (один раз, нужен sudo)
sudo ./scripts/setup-uinput.sh

# 3. Проверка, что всё живо
.venv/bin/layout-fixer devices
.venv/bin/layout-fixer state
.venv/bin/python scripts/spike_inject_test.py   # печатает текст инъекцией
```

## Настройка переключения раскладки

Демон переключает раскладку **инъекцией технической клавиши** — актуатора
(xkb-опция `grp:*_toggle`). По умолчанию это Scroll Lock: эта клавиша есть на
обеих клавиатурах и ничего не делает в современных приложениях.

```bash
.venv/bin/layout-fixer actuator show                    # что сейчас
.venv/bin/layout-fixer actuator set scrolllock --dry-run # показать, что изменится
.venv/bin/layout-fixer actuator set scrolllock           # применить
.venv/bin/layout-fixer actuator restore                  # вернуть как было
```

Что это меняет по сравнению с `grp:lalt_toggle`:

| Было (`grp:lalt_toggle`) | Стало (`grp:sclk_toggle` + демон) |
|---|---|
| Alt переключает язык при каждом нажатии | Alt переключает язык только при одиночном тапе |
| `Alt+Tab` переключает язык | `Alt+Tab` работает как обычно |
| `Ctrl+Alt+T` не открывает терминал | `Ctrl+Alt+T` работает |
| Scroll Lock LED показывает раскладку | Scroll Lock показывает раскладку (и переключает) |

## Запуск

На первом этапе — **режим наблюдения**: демон ничего не меняет, а пишет в лог,
что бы он исправил. Так видно качество распознавания и нет риска испортить текст.

```bash
.venv/bin/layout-fixer run                    # наблюдение (из конфига)
.venv/bin/layout-fixer run --mode fix         # включить автозамену
.venv/bin/layout-fixer run -v                 # подробный лог (видно каждое решение)
```

Постоянная работа как сервис:

```bash
./scripts/install-service.sh observe   # поставить и запустить
journalctl --user -u layout-fixer -f   # смотреть лог
systemctl --user kill -s SIGUSR1 layout-fixer   # пауза/продолжить на ходу
```

## Настройки

Файл `~/.config/layout-fixer/config.toml` создаётся при первом запуске.
Основное:

| Ключ | Смысл |
|---|---|
| `mode` | `observe` — только лог, `fix` — реально исправлять |
| `layouts` | раскладки; пусто — взять из настроек GNOME |
| `actuator` | клавиша-актуатор (`scrolllock`, `leftalt`, `menu`, `rightctrl`, `capslock`) |
| `trigger` | `alt_tap` — тап левого Alt переключает раскладку, `none` — не перехватывать |
| `min_word_length` | минимальная длина слова для проверки (по умолчанию 3) |
| `allow_short_words` | проверять слова короче `min_word_length` — предлоги и союзы, по умолчанию включено |
| `use_bigram` | исправлять ли слова, которых нет ни в одном словаре, «по похожести» (поймает имена и сленг, но может ошибиться; по умолчанию выключено) |
| `bigram_margin` | порог перевеса биграмм при `use_bigram = true` (2.5: больше — меньше ложных срабатываний) |
| `bigram_veto` | спрашивать биграммы перед правкой, подтверждённой словарём (по умолчанию включено, см. ниже) |
| `ignore_words` | слова, которые никогда не исправлять |
| `decisions_log` | путь к журналу решений (пусто — `~/.local/state/layout-fixer/decisions.log`, `"-"` — выключить) |
| `log_words` | писать ли в журнал сам текст слов |
| `settle_ms` | пауза после переключения раскладки перед печатью |
| `idle_fix_ms` | пауза в наборе, после которой слово исправляется без разделителя (0 — выключено) |
| `restore_layout` | возвращать исходную раскладку после правки (по умолчанию выключено) |
| `ignore_devices` | устройства ввода, чьи события не считать пользовательским вводом |

Проверить, как детектор рассуждает про конкретное слово:

```bash
.venv/bin/layout-fixer explain ghbdtn --layout us
```

## Наблюдение за работой

Демон ведёт **журнал решений** — не только исправления, но и все проверенные
слова и причины, по которым слово оставлено как есть. По нему строится отчёт:

```bash
layout-fixer report                 # сводка за всё время
layout-fixer report --days 1        # только за сутки
layout-fixer report --tail 0        # без списка последних записей
layout-fixer report --clear         # очистить журнал
```

### Отслеживание отменённых правок (`REVERT`)

Если вы только что исправили слово, а потом стёрли его — правка была лишней.
Демон запоминает введённое исправление и 30 секунд следит: если вы нажмёте
`Backspace` столько раз, сколько в слове букв, он запишет `REVERT`.

Это единственный доступный сигнал правды о ложных срабатываниях: сам детектор
уверен в своей правоте на 0.95 и проверить себя не может. Отчёт сразу показывает
долю мусора:

```
Ложных срабатываний: 2 из 5 (40.0% от исправлений)
Стёрто пользователем (топ 10):
    1× 'rfr' -> 'как'
    1× 'xnj' -> 'что'
```

Наблюдение снимается, если вы продолжили печатать, переключили раскладку, нажали
паузу или прошло 30 секунд. Стирание двух-трёх букв с последующей правкой
считается обычным редактированием, а не отменой.

Считаются все способы стирания: обычный `Backspace`, `Ctrl+Backspace` (удаление
слова), `Alt+Backspace`, `Shift+Backspace` и автоповтор при зажатом `Backspace`.
Нажатие модификатора само по себе наблюдение не снимает — иначе `Ctrl+Backspace`
обнулял бы его раньше, чем дойдёт до стирания.

Файл журнала: `~/.local/state/layout-fixer/decisions.log` (TSV, можно читать
глазами или разбирать скриптом). Если не хотите хранить текст набранных слов —
`log_words = false` в конфиге, тогда в журнале будут только виды решений.

## Как принимаются решения

1. Слово есть в словаре текущей раскладки → не трогаем.
2. Слова нет в текущей, но есть в другой раскладке → исправляем (уверенность 0.95).
3. Слова нет ни там, ни там → сравниваем «похожесть на слово» по биграммам,
   собранным из словарей; исправляем только при заметном перевесе (0.60).

### Вето по биграммам (`bigram_veto`)

Правило 2 смотрит только в словари и модель не спрашивает, поэтому короткий
латинский токен исправлялся безусловно: `ide` нет в `en_US`, а `шву` есть в
`ru_RU` — значит «переключить». На деле биграммы были против
(`us` −5.145 против `ru` −7.896): `ide` выглядит куда больше английским
словом, чем `шву` русским, и пользователь получал `шву` вместо `ide`.

Поэтому перед словарной правкой демон спрашивает модель биграмм: если текущая
раскладка выигрывает у другой на `bigram_margin` (2.5) — правка отменяется.
На историческом журнале (127 правок за 9 дней) это отменяет **ровно одну** —
ту самую `ide`, — и не задевает ни одной настоящей опечатки, включая все
16 трёхбуквенных (`rfr`→как, `xnj`→что, `lfq`→дай).

Модели собираются один раз при старте (~1.8 с) и кэшируются в процессе, поэтому
вето не добавляет задержки к первой правке. Работает независимо от `use_bigram`.

Чего вето **не** ловит: слова, чей русский эквивалент сам редкий, — тогда
биграммы честно считают его более «русским». Из реального журнала так
остались `dblt`→`виде`, `cgbx`→`спич`, `ahb`→`фри`. Для таких случаев
остаётся `ignore_words`.

Исправление никогда не выполняется:

* для слов короче двух букв — одна буква одинаково похожа на любой язык
  (у «d» → «в» перевес биграмм отрицательный);
* если слово есть в словарях **обеих** раскладок — это не опечатка, а
  двусмысленность: `bp` есть и в `en_US`, и как `из` в `ru_RU`;

* после `Enter`/`Tab`/`Escape` — эффект уже наступил (сообщение отправлено,
  команда выполнена, вкладка переключена), отменить его нечем. **Но при
  `idle_fix_ms > 0` слово обычно уже исправлено за паузу до Enter** — из-за
  этого Enter был причиной 9 отмен из 13 за первую неделю;
* если разделителя нет в целевой раскладке — сначала пробуется та же клавиша
  в ней: `&` в русской раскладке не существует, там на ней `?`, и слова с
  вопросительным знаком исправляются. Если там буква (`[` -> `Х`), знак буквой
  не подменяется;
* если нажат `Shift` в момент правки — ждём его отпускания, а не отменяем:
  иначе `?`, `!`, `(`, `&` и заглавные не исправлялись бы никогда;

* если слово правилось руками (был `Backspace` **внутри этого слова** —
  `Backspace` по пустому буферу, например сразу после автозамены, не считается);
* если набирались цифры или символы, а не буквы;
* если зажат `Ctrl`/`Alt`/`Super` — это горячая клавиша, а не текст;
* **если зажат `Shift` или включён `Caps Lock`** — решение принимается по
  `word.lower()`, а инъекция идёт в реальное состояние клавиатуры, и демон
  напечатал бы «ПРИВЕТ» вместо «привет». Проверяется в момент инъекции, а не
  в момент решения: между ними пользователь успевает нажать `Shift`;
* если слово короче `min_word_length` или длиннее `max_word_length`.

Разделитель при этом может быть любым, кроме `Enter`/`Tab`/`Escape`: цифры,
`/`, `+` и прочее стираются и печатаются заново без побочных эффектов. Раньше
здесь стоял белый список «безопасных» разделителей, и любая запятая вне него
отменяла правку — за первые дни 4 из 12 отмен были напрасными.

## Ограничения (честно)

* **Демон не знает, какое приложение в фокусе.** В терминале, редакторах кода и
  полях паролей автоматика бывает вредна — не существует способа узнать это на
  Wayland без дополнительных слоёв. Поэтому начинать стоит с режима наблюдения.
  Полезно также `ignore_words` и пауза по `SIGUSR1`.
* Порядок «удалить → переключить → напечатать → вернуть раскладку» виден глазом
  как короткое мигание текста: сначала приложение получает неверное слово, и
  только потом мы его заменяем (отменить уже доставленные нажатия нельзя).
  Раскладка возвращается в ту, в которой вы печатали, — иначе после каждой
  опечатки пришлось бы жать Alt, чтобы продолжить в прежней. Отключается через
  `restore_layout = false`, плата за возврат — лишние `settle_ms` на правку.
* Курсор: буфер слова сбрасывается на стрелках, `Home`/`End`, кликах мышью в
  другом окне и любых горячих клавишах. Если курсор сдвинули чем-то, чего мы не
  видим, автозамена может сработать неточно — поэтому разделители вроде `Enter`
  исключены из исправления.
* Читается вся клавиатура целиком: в буфере демона на секунды оказываются
  набранные слова (как у любого Punto Switcher). Ничего не сохраняется на диск
  и не отправляется по сети.

## Устройство

```
src/layout_fixer/
  xkb.py             таблицы раскладок, сгенерированные через libxkbcommon
  hunspell.py        проверка орфографии через libhunspell (ctypes, с аффиксами)
  gnome_settings.py  чтение настроек GNOME + подписка на смену раскладки
  injector.py        виртуальная клавиатура (/dev/uinput)
  reader.py          чтение всех клавиатур, hot-plug
  keys.py            состояние модификаторов (Shift, Caps Lock, AltGr)
  buffer.py          буфер текущего слова
  detector.py        решение «это не та раскладка»
  fixer.py           стереть и напечатать заново
  layout_state.py    текущая раскладка и её переключение
  daemon.py          сборка всего в один цикл
  cli.py             командная строка
```

Почему таблицы раскладок генерируются, а не написаны руками: они берутся из
тех же файлов `xkeyboard-config` через `libxkbcommon`, что использует и Mutter,
поэтому маппинг совпадает с реальным поведением системы (включая Shift, Caps
Lock, AltGr и варианты раскладок).

## Разработка

```bash
.venv/bin/python -m unittest discover -s tests -v   # 156 тестов конвейера
.venv/bin/layout-fixer sniff                        # наблюдать клавиатуру и раскладку
.venv/bin/python scripts/spike_inject_test.py       # проверить инъекцию (печать/Backspace/раскладка)
```

Полезно знать при отладке:

* индикатор текущей раскладки — `mru-sources` (первый элемент); ключ `current`
  в GNOME устарел и игнорируется, `org.gnome.Shell.Eval` заблокирован;
* `sniff` — самый быстрый способ понять, что мы видим с клавиатуры;
* запускать демон лучше сервисом: он стартует с чистым окружением. Встроенный
  терминал snap-версии VS Code подменяет `GTK_*`/`GIO_*` переменные и ломает
  нативные GTK-приложения.
